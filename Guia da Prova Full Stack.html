Guia da Prova Full Stack

Todo o conteúdo da prova é uma única viagem: o dado sai de um formulário, passa pelo servidor, vai para o banco e volta como uma página pronta. Cada bloco deste guia é uma parada dessa viagem.

1 · navegadorFormulárioA pessoa preenche e clica em Enviar 2 · HTTPGET ou POSTOs dados vão para uma rota, como /cadastrar 3 · Node + ExpressRotaA função da rota recebe os dados 4 · porta 27017MongoDBGrava ou busca no banco 5 · viewsEJSMonta a página com o resultado e devolve

Para explicar aos colegas: o servidor é um garçom. O formulário é o pedido, a rota é a mesa para onde o pedido vai, o banco é a cozinha e o EJS é o prato montado que volta para a mesa.

Bloco 1JavaScript e servidor

O que é o Node.js?

O JavaScript nasceu para rodar dentro do navegador. O Node.js é um programa que roda JavaScript fora do navegador, direto no computador. É ele que permite usar JavaScript para criar um servidor.

  • No navegador, o JS mexe na página: botões, canvas, getElementById.
  • No Node.js, o JS recebe pedidos da internet, lê arquivos e conversa com o banco.
  • Para rodar um arquivo: node servidor.js no terminal.

O que é o npm?

npm = Node Package Manager, ou "gerenciador de pacotes do Node". Um pacote é um código pronto que outra pessoa escreveu e publicou. O npm baixa esses pacotes para o seu projeto, como uma loja de aplicativos para código.

O que é o Express?

É um pacote que facilita muito criar o servidor. Sem ele, você teria que tratar cada detalhe do protocolo HTTP na mão. Com ele, criar uma rota é uma linha:

package.json, package-lock.json e node_modules

ArquivoO que éAnalogia
package.jsonA lista de pacotes que o projeto usa, com a versão aproximada de cada um. Você pode ler e editar.A lista de compras
package-lock.jsonGerado sozinho. Anota a versão exata de cada pacote e dos pacotes que eles usam por dentro, para todo mundo instalar exatamente igual. Não se edita.A nota fiscal, com marca e lote de cada item

Se alguém apagar a node_modules, basta rodar npm install na pasta do projeto: o npm lê o package.json e o -lock e baixa tudo de novo.

Estrutura do projeto

  • public: o servidor entrega do jeito que está, igual para todo mundo (express.static).
  • views: o servidor monta a página na hora, com os dados de cada pedido (resposta.render).

O que é a porta?

O computador é um prédio e o IP é o endereço dele. A porta é o número do apartamento: vários programas podem rodar no mesmo computador, cada um "morando" numa porta diferente.

PortaQuem usa
80Padrão da web. É a que o slide usa (server.listen(80)), e o acesso é com localhost direto
3000Muito usada em desenvolvimento. O acesso é com localhost:3000
27017Padrão do MongoDB. É por ela que o servidor conversa com o banco

localhost significa "este mesmo computador". De outro PC na mesma rede, use o IP da máquina, por exemplo 192.168.1.101:3000.

Rotas

Uma rota é a combinação de um método (GET ou POST) com um caminho (/cadastrar). Cada rota é um balcão de atendimento do servidor, com uma função que roda quando alguém chega nele.

GET /cadastrar e POST /cadastrar são rotas diferentes, mesmo com o mesmo caminho.

Gravar e buscar no banco (resumo)

  • Gravar: colecao.insertOne(dados, function (err) { ... })
  • Buscar: colecao.find(filtro).toArray(function (err, items) { ... })
  • Atualizar: await colecao.updateOne(filtro, { $set: { campo: novoValor } })

Os detalhes estão no Bloco 5.

Bloco 2Requisições e métodos

O que é uma requisição?

É um pedido que o navegador (cliente) manda para o servidor. O servidor sempre devolve uma resposta. Essa conversa segue as regras do protocolo HTTP.

  • Digitar localhost:3000/listar na barra de endereço é uma requisição.
  • Clicar em Enviar num formulário é uma requisição.
  • Clicar num link é uma requisição.

Toda requisição tem um método (GET, POST...), um caminho (/listar) e, às vezes, dados (o que foi digitado no formulário).

O que o método significa para o servidor?

O método diz a intenção do pedido. O servidor usa o método e o caminho juntos para escolher qual rota vai atender.

GETPOST
IntençãoPegar / buscar alguma coisaEnviar / gravar alguma coisa
Onde vão os dadosNa URL: /buscar?email=ana@email.comNo corpo da requisição, invisível na URL
Como o servidor lêrequisicao.query.emailrequisicao.body.email
Precisa de body-parser?NãoSim
Dá para salvar nos favoritos?Sim, a busca fica na URLNão
Quando usarBuscas, listagens, abrir páginasCadastro, login, senha, atualizar

Regra prática: senha nunca vai por GET, porque apareceria na URL e no histórico do navegador.

O body-parser

No POST os dados vêm no corpo da requisição, num formato que o Express não lê sozinho. O body-parser "abre o envelope" e coloca os dados em requisicao.body. Sem ele, requisicao.body fica undefined.

Como as rotas funcionam no servidor

Quando chega uma requisição, o Express procura, de cima para baixo, a primeira rota com o mesmo método e o mesmo caminho:

  1. Chegou POST /cadastrar.
  2. O Express procura um app.post("/cadastrar", ...) e roda a função dele.
  3. A função lê os dados, fala com o banco e responde.
  4. Se nenhuma rota combinar, o navegador mostra Cannot GET /caminho (ou Cannot POST).

A ligação entre o HTML e a rota está no formulário. Os dois lados têm que bater exatamente:

As três formas de responder

ComandoO que faz
resposta.send("texto")Devolve um texto simples
resposta.redirect("pagina.html")Manda o navegador ir para outra página
resposta.render("arquivo", { dados })Monta uma página EJS com os dados (Bloco 4)

Cada requisição recebe uma resposta só. Duas respostas na mesma rota dão o erro Cannot set headers after they are sent.

Bloco 4EJS

O problema que o EJS resolve

Um .html em public é estático: mostra sempre a mesma coisa. Mas depois de cadastrar, a página tem que dizer "Leitor Ana cadastrado", e na busca tem que listar os leitores que vieram do banco. Esse conteúdo muda a cada pedido.

O EJS é um HTML com buracos. O servidor preenche os buracos com os dados e devolve o HTML pronto. O navegador nem fica sabendo que existiu um EJS.

Configuração (uma vez, no servidor)

As duas tags

TagO que fazExemplo
<%= variavel %>Mostra o valor na página<h2><%= mensagem %></h2>
<% codigo %>Executa JavaScript, sem mostrar nada<% if (...) { %> e <% for (...) { %>

Para lembrar: o = da primeira tag é de "mostre o resultado".

Como o servidor manda os dados

O nome no render vai sem a extensão .ejs e sem o nome da pasta, porque o app.set("views", ...) já diz onde procurar.

Mostrando uma lista do banco (if + for)

Por que o { e o } ficam em tags separadas: o for abre na primeira tag, o HTML do meio se repete uma vez para cada leitor, e o } fecha o for na outra tag. Tudo entre elas é o corpo do laço.

Bloco 5MongoDB

Banco, collection e documento

O MongoDB é um banco não relacional (NoSQL): em vez de tabelas com linhas e colunas, ele guarda documentos parecidos com objetos do JavaScript.

MongoDBEquivalente em SQLAnalogia
Banco (database)BancoO arquivo de aço inteiro
CollectionTabelaUma gaveta ("leitores", "livros")
DocumentoLinha (registro)Uma ficha dentro da gaveta

O banco e a collection nascem sozinhos no primeiro insertOne. Não precisa criar nada antes no Compass.

A conexão (sempre os mesmos 4 passos)

Lendo a connection string mongodb://127.0.0.1:27017:

  • mongodb:// é o protocolo, como o http:// dos sites.
  • 127.0.0.1 é "este computador", o mesmo que localhost.
  • 27017 é a porta padrão do MongoDB.

No Compass, essa é a string que já aparece em New Connection (mongodb://localhost:27017). No código, prefira 127.0.0.1: nas versões novas do Node, localhost pode ser traduzido para o endereço IPv6 ::1, e a conexão falha com ECONNREFUSED ::1:27017.

Por que a versão 4.12: os slides usam callbacks (function (err) {...}) dentro do insertOne e do toArray. A partir da versão 5 do pacote, os callbacks foram removidos e esse código para de funcionar.

Gravar (Create): insertOne

Por que a resposta fica dentro da função: gravar no banco leva um tempinho. A função (callback) só roda quando o banco termina. Se o render ficasse fora dela, a página diria "sucesso" antes de o banco responder.

Buscar (Read): find + toArray

Como o filtro funciona: o find traz os documentos em que todos os campos do filtro são iguais.

FiltroO que traz
{}Todos os documentos da collection
{ db_email: "ana@email.com" }Quem tem esse e-mail
{ db_email: "ana@email.com", db_senha: "123" }Quem tem esse e-mail e essa senha (é assim que o login funciona)

O toArray existe porque o find não devolve os documentos direto: ele devolve um "cursor" (um ponteiro). O toArray transforma o resultado num array normal.

Atualizar (Update): updateOne + $set

  • Filtro: quem vai ser atualizado.
  • $set: o que muda. Só os campos dentro dele são alterados, o resto do documento fica igual.
  • matchedCount: quantos documentos combinaram com o filtro. Se for 0, ninguém foi encontrado.
  • async / await / try / catch: outro jeito de esperar o banco, no lugar do callback. O await espera o banco antes de ir para a próxima linha, e o catch pega os erros. A palavra async precisa estar na função da rota para o await funcionar.

Resumo dos métodos

OperaçãoMétodoResultado
CreateinsertOne(dados, callback)Grava um documento
Readfind(filtro).toArray(callback)Array com os documentos encontrados
Updateawait updateOne(filtro, { $set: {...} })result.matchedCount
Delete (fora da prova)await deleteOne(filtro)result.deletedCount

ProjetoBiblioteca: Create, Read e Update

Cadastro de leitores de uma biblioteca, com cadastrar, listar, buscar por e-mail, login e troca de senha. Para trocar de cenário (escola, loja, academia), basta mudar os nomes: o banco, a collection, os campos do formulário e os db_ no servidor.

Todas as rotas foram testadas com o Node 22 e os mesmos pacotes da prova, usando uma collection simulada em memória no lugar do MongoDB. O teste contra o Compass de verdade é o único que ficou faltando.
